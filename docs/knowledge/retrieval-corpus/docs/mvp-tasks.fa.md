# Flux Engine MVP — بک‌لاگ اجرایی

> این بک‌لاگ ۲۸ تسکی برای محصول گسترده‌تر نگه داشته شده است. برنامهٔ فعال طبق درخواست جدید کاربر، [۸ تسک دموی شخصی](personal-demo.fa.md) است.

مرجع تحویل: [محصول Windows با حافظهٔ محلی ۰٫۵](desktop-product.fa.md). [طراحی موتور](mvp-design.fa.md) و [نیازمندی اولیه](mvp-requirements.fa.md) قرارداد هسته‌اند؛ محدودیت بدون پنل طبق درخواست جدید کاربر کنار گذاشته شده است. وضعیت تمام تسک‌ها: TODO. این سند برنامهٔ اجراست، نه گزارش قابلیت‌های ساخته‌شده.

تخمین‌ها نفرـروز توسعه و تست برای یک توسعه‌دهنده‌اند؛ زمان انتظار ارائه‌دهنده و پایلوت در آن‌ها نیست. هر تسک با artifact و معیار پذیرش بسته می‌شود. P0 یعنی ضروری برای MVP، P1 یعنی ضروری برای تحویل قابل استفاده پس از هسته.

جمع اولیه: ۱۳ تا ۱۹ نفرـروز برای موتور کامل با runner و کنترل crash؛ حدود ۳ تا ۴ هفتهٔ کاری یک نفر، با فرض دسترسی آماده. این تخمین اختصاصی این دامنه است و جایگزین برآورد تاریخی چارت ۹ نقشی نیست. runner Windows و جزئیات صورتحساب ارائه‌دهنده بیشترین عدم قطعیت را دارند.

تست همراه هر تسک نوشته و اجرا می‌شود؛ مرحله E تجمیع و آزمون خرابی است. قبل از FLX-16 چرخهٔ fake باید کامل باشد. FLX-17 تنها مرحلهٔ نیازمند مصرف واقعی API است؛ بررسی وضعیت مدل با GET به‌تنهایی اثبات کیفیت/سازگاری تولید نیست.

## نخستین نقطهٔ نمایش و نقطهٔ پایان

نقطهٔ نمایش داخلی: یک Task سند با Fake Provider از ورودی تا خروجی و هزینه طی شود؛ بعد از restart قابل مشاهده باشد. این نمایش اثبات تکمیل کل MVP نیست.

پایان هسته: API/CLI قابل نصب، پنج نقش قابل route، مسیر کد در runner، ۱۲ تست و آزمون‌های خرابی پاس، مستندات کامل و گزارش روشن وضعیت adapter. این به‌تنهایی پایان محصول نیست. اگر مدل/تعرفه تأیید نشود، تحویل fake ممکن است ولی «آمادهٔ اجرای زنده» اعلام نمی‌شود.

افزودهٔ محصول: حدود ۱۴ تا ۲۴ نفرـروز؛ کل موتور و نرم‌افزار: حدود ۲۷ تا ۴۳ نفرـروز، معادل ۶ تا ۹ هفتهٔ کاری یک نفر با عدم قطعیت runner، مدل‌ها و بسته‌بندی. برآورد هستهٔ ۱۳ تا ۱۹ روز، برآورد کل نرم‌افزار نیست.

ترتیب نمایش به کاربر: ۱) پوستهٔ Windows و ساخت پروژه/Task با fake؛ ۲) حافظهٔ محلی و مصرف قابل مشاهده؛ ۳) اجرای کامل و بررسی نتیجه؛ ۴) اتصال GapGPT و آزمون دقت؛ ۵) نصاب و پشتیبان‌گیری. هر نمایش محدودیت‌های خودش را دارد.

پایان محصول: تمام FLX-01 تا FLX-28 با معیارها بسته شوند و کاربر از پنجرهٔ Windows پروژه بسازد، Task اجرا کند، هزینه و حافظه را مدیریت کند، نتیجه را بپذیرد و بعد از راه‌اندازی مجدد داده‌اش را داشته باشد. پذیرش انسانی در این دامنه است؛ Alacrity OS و چندکاربره و چارت ۹ نقشی برای بعد می‌مانند.
