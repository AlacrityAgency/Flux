# بازنویسی تجربهٔ Flux Demo

نسخهٔ ۰٫۲ — ۷ سپتامبر ۲۰۲۶

## مبنای اجرا

نسخهٔ اولیهٔ کاربر یک برنامهٔ FastAPI با صفحهٔ HTML و ۱۸ تست بود. بازنویسی روی همین فناوری انجام شد تا سرویس محلی و داده‌های قبلی قابل استفاده بمانند. رابط محصول اکنون گفت‌وگومحور و فارسی است. تصمیم قدیمی PySide6 برای این پیاده‌سازی جای خود را به رابط وب محلی در پنجرهٔ app مرورگر داده است؛ اتصال خارجی برای بارگذاری UI یا فونت لازم نیست.

## ساختار رابط

- سمت راست: برند Flux، کار جدید، جست‌وجو، حافظه و مصرف، تاریخچه و وضعیت فضای شخصی.
- مرکز: صفحهٔ شروع با سه نمونه، گفت‌وگوهای چندپیامی و ورودی ثابت پایین صفحه.
- پنل اختیاری سمت چپ: پنج نقش، وضعیت واقعی فراخوانی‌ها، مصرف و شواهد.
- صفحهٔ حافظه: یادداشت فعال/غیرفعال، نسخه، ویرایش و حذف با تأیید.
- صفحهٔ مصرف: خرج، رزرو، هزینهٔ نامعلوم، مانده و تفکیک مدل؛ تغییر سقف روزانه.
- تنظیمات: وضعیت fake/live، مدل‌های درخواستی و روشنایی. نمایش وضعیت، تأیید دسترسی API محسوب نمی‌شود.

## جزئیات طراحی

پس‌زمینهٔ خاکستری خنثی، نوار کناری تیره‌تر و رنگ نعنایی محدود برای فعالیت/اقدام اصلی. فونت متغیر Vazirmatn به‌صورت محلی همراه مجوز OFL بسته‌بندی شده است. کد در بلوک LTR و متن فارسی RTL نمایش داده می‌شود. حالت روشن، صفحهٔ باریک، focus صفحه‌کلید، عنوان دکمه‌های آیکونی و reduced motion لحاظ شده‌اند.

Enter پیام می‌فرستد و Shift+Enter خط جدید می‌سازد؛ Ctrl+K گفت‌وگوی جدید باز می‌کند. معیار پذیرش باید مشخص باشد و از پنجرهٔ تنظیمات کار قابل تغییر است. هر پیام یک Run مستقل با سقف مستقل است؛ پاسخ قبلی به‌صورت زمینهٔ محدود و علامت‌گذاری‌شده منتقل می‌شود. سقف روزانه مجموع اجراها را محدود می‌کند.

## تغییرات رفتاری

- ارسال background شناسهٔ Run را فوری برمی‌گرداند؛ UI پیشرفت واقعی را poll می‌کند و با وضعیت پایانی متوقف می‌شود.
- به‌جای نام و آدرس artifact، متن واقعی output.content نمایش داده می‌شود.
- حالت fake و شواهد شبیه‌سازی‌شده برچسب روشن دارند؛ تأیید Head یا Reviewer ثابت و نمایشی نیست.
- Markdown محدود و escape‌شده نمایش داده می‌شود؛ HTML مدل اجرا نمی‌شود. فایل پیوست فقط متن محدود است.
- تاریخچهٔ قدیمی بدون حذف Runها به گفت‌وگوهای قابل مشاهده منتقل می‌شود.
- حافظهٔ انتخاب‌شده، نسخه و منابع هر Run در صفحهٔ همان پیام قابل مشاهده‌اند.
- هر ارسال شبکه، حتی retry، بودجه و رکورد مصرف خودش را دارد؛ Head حداکثر دو ارسال دارد.
- تسویه با snapshot قیمت تماس انجام می‌شود؛ usage ناموجود رزرو را در حالت نامعلوم نگه می‌دارد.
- پذیرش انسانی به hash خروجی ثبت‌شده متصل است. معیار جاافتاده یا check ناموفق/not_run مانع قبولی می‌شود.
- لغو در میانهٔ تماس، پاسخ دیررس را فقط برای هزینه ثبت می‌کند؛ Agent بعدی شروع نمی‌شود.

## محدودیت‌های فعلی

اجرای واقعی GapGPT در این بازنویسی تست نشده؛ شناسه و تعرفه‌ها تأیید نشده‌اند. برآورد توکن تضمین صورتحساب ارائه‌دهنده نیست. برنامه آموزش مدل، اجرای shell، sandbox، اصلاح مستقیم فایل پروژه و تست کد ندارد. بازبینی مدل جای تست یا قضاوت انسانی را نمی‌گیرد.

حافظهٔ فعلی جست‌وجوی واژگانی سبک است، نه embedding یا FTS5؛ مدل فقط اطلاعات مرتبط را در context می‌گیرد. متن snapshot در Runهای قبلی با حذف یادداشت از حافظه پاک نمی‌شود و این رفتار در تأیید حذف توضیح داده می‌شود.

Resume خودکار تماس نامعلوم و حلقهٔ اصلاح خودکار فعال نیست؛ کاربر اصلاح را در پیام جدید ثبت می‌کند. بازکردن پس از crash اجرای قدیمی را خودکار تکرار نمی‌کند. تعرفه‌ها از فهرست قبلی کاربر آمده‌اند و برای fake صرفاً تخمینی هستند. روز بودجه بر مبنای UTC و روز ایجاد Run است؛ timezone سفارشی و تغییر روز برای Run باز پیاده‌سازی نشده است.

نسخهٔ Windows از Edge یا Chrome نصب‌شده برای پنجرهٔ app استفاده می‌کند. در نبود هر دو، مرورگر پیش‌فرض باز می‌شود و بستن آن الزاماً سرویس را نمی‌بندد. برای حالت app، با بسته‌شدن فرایند مرورگر اختصاصی، سرویس محلی خاموش می‌شود.

## راستی‌آزمایی

تست‌های موتور/API با Fake Provider اجرا شده‌اند. تست مرورگر شامل آغاز گفت‌وگو، مسیر پنج نقش، پذیرش، پیام بعدی، reload، ذخیرهٔ حافظه، مصرف، حالت روشن و نمای باریک است. تصاویر در پوشهٔ screenshots ذخیره شده‌اند. هیچ تماس تولیدی به API واقعی برای این تست‌ها لازم نیست.
