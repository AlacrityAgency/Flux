# Component Contracts

Specify each important component by purpose, content, anatomy, responsive behavior, and applicable states. Include default, focus, selected, disabled, loading, error, empty, and success only when those states can occur. Describe the user action and feedback in each state; a selector's existence is not evidence that the behavior works.

Use real or representative copy and data. Check long names, missing images, large values, localized dates and currencies, and empty results. Preserve stable dimensions for fixed-format elements so dynamic content does not shift nearby controls. Record truncation or wrapping rules where content has a hard spatial limit.

For a working prototype, expose states in a component gallery when the project already uses Storybook or when a library of reusable components warrants it. For a single page, an in-page or test fixture may be simpler. Keep the implementation within the existing framework and conventions.
